# Humans vs AI — полный пул экранов и готовность игрового цикла к тестам

**Статус:** source of truth для проектирования интерфейсов перед игровым тестом  
**Дата аудита:** 2026-07-15  
**Область:** пользовательские экраны, необходимые API/данные, графические ассеты и порядок реализации

---

## 1. Итог аудита

Серверный каркас ежедневной битвы уже существует: создание события, вступление,
автоматическое назначение армии, семь доктрин, неизменяемый Order, resolver,
прогрессия, карта, история захватов и итоговый отчёт. Клиент сейчас покрывает только
узкую вертикаль: вступление → выбор доктрины без комментария → таймер → короткий
результат, плюс модальное окно глобальной карты.

Для тестируемого полного цикла нужны **12 экранов P0**, **7 экранов P1** и
**5 экранов P2**. Главные блокеры P0 находятся не в графике, а в контрактах данных:

1. Order не хранит ссылку на комментарий.
2. Нет API списка допустимых комментариев своей команды.
3. Нет пользовательского действия для обвинения/проверки предполагаемого шпиона.
4. Нет публичного профиля и стабильной ссылки на него.
5. Нет ежедневного leaderboard и персональной строки итогов битвы.
6. Медали хранятся строками; каталог, metadata и связь с изображениями не оформлены.

## 2. Полный маршрут игрока

```text
Открытие Daily Post
  → вступление в событие
  → назначение Green/Blue
  → briefing активной территории
  → обсуждение в Reddit War Room
  → выбор комментария союзника
  → выбор одной из 7 доктрин
  → подтверждение неизменяемого Order
  → контрразведывательное действие (если доступно)
  → ожидание cutoff / просмотр карты
  → итог боя
  → личные XP, rank и medals
  → ежедневный leaderboard
  → публичный профиль / история службы
  → следующая битва
```

Каждый P0-сценарий должен быть проходим на desktop и mobile внутри Devvit webview.
Основные формы и таблицы следует делать DOM-интерфейсами. Phaser остаётся для
визуальной сцены боя и декоративных игровых состояний.

## 3. Что реализовано сейчас

| Возможность | Текущее состояние | Вывод для UI |
|---|---|---|
| Bootstrap текущего дня | `GET /api/bootstrap` | Можно строить единый роутер состояния дня |
| Вступление | `POST /api/player/join` | Работает, но экран требует briefing и явного результата назначения |
| Балансировка армий | Участник получает `assignedArmy` и power snapshot | Показывать объяснение без раскрытия лишней внутренней логики |
| Order | `POST /api/orders` принимает только `doctrineId` | Нельзя реализовать каноническую ссылку на комментарий без изменения API |
| Неизменяемость Order | Повторная отправка возвращает существующий Order | Нужен экран review/confirm до финальной отправки |
| 7 доктрин | Контракт и матрица существуют | Нужны игровые карточки и контекстная шпаргалка counters |
| Spy assignment | Bootstrap может вернуть cover army, objective и hint | Есть назначение, но нет полного интерфейса миссии/контрразведки |
| Resolver | Итог содержит доктрины, scores, signals, awareness, spy influence | Данных достаточно для расширенного боевого отчёта |
| Карта | `GET /api/global-map`, 30 клеток 6×5 | Работает как модальное окно; требуется полноценная игровая композиция |
| История территории | Capture records и ссылки на Daily Post | Можно построить timeline боя территории |
| Прогрессия | XP, rank, streak, две базовые medals, ledger | Нет публичного/личного API профиля и детального результата дня |
| Campaign leaderboard | Агрегируется для финального отчёта | Логику можно переиспользовать, но ежедневного endpoint нет |
| Ранги | 48 уровней и растровые изображения | Готовая основа профиля, leaderboard и reward reveal |
| Медали | 114 изображений присутствуют | Нужен каталог ID → название → условие → rarity → asset |

## 4. Экраны P0 — обязательны для первого полного теста

### P0-01. Daily Command Center

**Назначение:** единая стартовая точка текущего игрового дня.

Показывает: фазу дня, таймер, активную территорию, владельца, назначенную армию,
статус Order, статус миссии и быстрые переходы к War Room, карте и профилю.

Состояния: не вступил; вступил; Order не отправлен; Order зафиксирован; cutoff;
resolved; нет активного боя; campaign complete; ошибка загрузки.

**Данные:** расширенный `GET /api/bootstrap`.  
**Графика:** фон штаба, портрет/эмблема армии, thumbnail территории, фазовые индикаторы.

### P0-02. Вступление и назначение армии

**Назначение:** понятное подтверждение участия вместо одиночной кнопки.

Шаги: правила участия → Join → reveal Green/Blue → временный flair → CTA в briefing.
Нужно явно сообщить, что команда назначается только на текущий день, а глобальный
профиль остаётся нейтральным.

**API:** существующий `POST /api/player/join`.  
**Графика:** две армейские карточки, анимация назначения, rank badge игрока.

### P0-03. Briefing сегодняшней битвы

**Назначение:** объяснить, за какую территорию идёт бой и что игрок должен сделать.

Показывает: название и изображение территории, текущий owner, Green/Blue/AI,
краткую цель дня, фазу, cutoff, ссылку на командную ветку и checklist действий.

**API:** bootstrap + territory metadata; metadata местности следует добавить.  
**Графика:** растровый establishing shot территории, мини-карта, погодный/terrain overlay.

### P0-04. Выбор командного комментария

**Назначение:** выбрать аргумент сокомандника, на котором основан Order.

Dropdown должен содержать только допустимые комментарии текущей Cover Army:
автор, flair на snapshot, короткий excerpt, время, permalink. Собственный,
удалённый, поздний и некомандный комментарии недоступны с видимой причиной.

Обязательны поиск/пагинация, обновление списка, empty state и fallback при отсутствии
чужих комментариев.

**Новый API:** `GET /api/battles/current/eligible-comments?cursor=...`.  
**Новый тип:** `EligibleComment { id, authorUsername, excerpt, createdAt, permalink,
teamAtSnapshot, eligibility }`.

### P0-05. Формирование Doctrine Order

**Назначение:** связать выбранный комментарий с одной из семи доктрин.

Показывает семь карточек: название, пиктограмма, короткая фантазия, три победы и
три поражения. После выбора — summary `комментарий + доктрина`.

**Изменение API:** `OrderRequest { doctrineId, sourceCommentId }`; в сохранённый
`DoctrineOrder` добавить `sourceCommentId` и безопасный `sourceCommentPermalink`.

**Графика:** семь уникальных doctrine cards, иконки и counter-diagram.

### P0-06. Финальное подтверждение Order

**Назначение:** защитить игрока от случайной необратимой отправки.

Отдельное подтверждение показывает выбранный комментарий, доктрину, команду и
предупреждение «после отправки изменить нельзя». После успеха — timestamp,
locked-состояние и ссылка на исходный комментарий.

Состояния: validation; комментарий стал недоступен; cutoff наступил; duplicate;
network retry; success.

### P0-07. Контрразведка: подозрение на шпиона

**Назначение:** выбрать комментарий игрока своей публичной команды и отметить,
что его автор предположительно является внедрённым шпионом.

Экран похож на Comment Picker, но действие относится к **автору комментария**, а
не к доктрине. Нужны лимит попыток, срок, подтверждение и безопасная формулировка:
это игровое предположение, не публичное обвинение и не повод для harassment.

**Новые API:**

- `GET /api/battles/current/counterintelligence-candidates`;
- `POST /api/spy/suspicions { commentId, suspectedUserId }`;
- `GET /api/spy/suspicions/me`.

Сервер должен хранить battle-local попытку, не публиковать username автоматически
и не начислять награду за массовые обвинения.

### P0-08. Оперативная карта кампании

**Назначение:** показать общую войну и текущий фронт.

Показывает 30 клеток 6×5, владельцев, Today, Next, счёт территорий сторон и статус
кампании. Выбор клетки открывает инспектор территории. Mobile использует pan/zoom
или компактную сетку с отдельным bottom sheet.

**API:** существующий `GET /api/global-map`.  
**Графика:** существующая world map как база, owner overlays, fog/scan effects,
маркеры Today/Next. Архитектура должна позволять позднее расширение до 150 точек.

### P0-09. Территория и история боёв

**Назначение:** объяснить, что происходило на конкретной точке.

Показывает: изображение территории, owner, координаты, Today/Next, timeline всех
боёв, переходы владения, winner и ссылку на соответствующий Daily Post.

Для resolved-боя открывается краткая карточка доктрин и итогового счёта; для этого
capture history необходимо расширить либо добавить endpoint деталей battle.

### P0-10. Визуальный экран сегодняшнего боя

**Назначение:** эмоциональное представление активной территории без ложной
симуляции результата до cutoff.

До resolve показывает противостояние Green/Blue/AI, выбранную территорию, фазу и
агрегированные разрешённые публичные сигналы. После resolve переходит в playback:
reveal трёх доктрин → три duel → winner → смена owner.

**Графика:** battlefield background по terrain, Green/Blue/AI units, sprites FX,
doctrine effects и итоговый capture banner. Центральное поле не перекрывается
постоянными панелями; подробности находятся в drawer.

### P0-11. Daily Battle Report и личные награды

**Назначение:** главный reward-момент дня.

Показывает: три доктрины, три duel, scores, public signal vs hidden result,
AI awareness, spy influence, старого/нового owner и Next Objective. Личный блок:
XP before/awarded/after, breakdown, rank progress, rank-up, новые medals и streak.

**Изменение API:** bootstrap summary должен вернуть персональную ledger entry,
новые медали отдельно от общей коллекции и безопасные агрегаты боя.

### P0-12. Ежедневный leaderboard битвы

**Назначение:** показать участников конкретного дня и их подтверждённый результат.

Строка: position, username, army, rank icon/title, XP awarded, итог миссии,
полученные сегодня medals. Текущий игрок закреплён даже вне top-N. Нужны фильтры
All/Green/Blue, пагинация и ссылка на профиль.

**Новый API:** `GET /api/battles/:battleId/leaderboard?army=&cursor=`.  
**Сортировка P0:** `xpAwarded DESC → mission outcome → username`; окончательное
правило должно быть утверждено до реализации.

## 5. Экраны P1 — нужны для качественного закрытого теста

### P1-01. Личный профиль

Включает Reddit username, rank 1–48, XP progress, streak, число битв, победы,
службу Green/Blue, последние бои, medals и permalink публичной версии.

### P1-02. Публичный профиль по ссылке

Стабильная ссылка вида `.../profile/<publicSlug>` должна открывать тот же read-only
профиль любому пользователю. Не показывать userId, скрытые Orders до resolve,
spy history без declassification, приватные роли и внутренние reliability-данные.

**Новые API:**

- `GET /api/profiles/me`;
- `GET /api/profiles/:publicSlug`;
- серверный canonical share URL.

Если Devvit deep-link не может гарантировать внутренний route, fallback-ссылка
должна вести на закреплённый app post с query/hash, который открывает профиль.

### P1-03. Коллекция медалей

Сетка unlocked/locked, rarity, прогресс, дата и battle выдачи. Нужен отдельный
каталог, а не прямое отображение строк из `RewardSummary.medals`.

### P1-04. Детали медали / reward reveal

Название, изображение, условие, rarity, дата, связанная битва и share action.
Reward reveal используется после Daily Report, но не блокирует переход дальше.

### P1-05. Глобальный leaderboard

Campaign/season ranking: XP, victories, participations, rank, streak и medals.
Можно переиспользовать сортировку финального campaign report.

### P1-06. Архив Daily Battles

Список дней с территорией, winner, owner transition и ссылкой на отчёт. Нужен для
возврата к пропущенному результату и навигации из профиля.

### P1-07. Doctrine Codex

Семь доктрин, полная матрица и интерактивное сравнение. Контекстная мини-версия
открывается из Order, полная — из меню/профиля.

## 6. Экраны P2 — после проверки основного цикла

1. **Role Mission Center** — Captain/Deputy и функциональные роли.
2. **Spy Mission Center** — acceptance, Cover Army, Secret Word и результат миссии.
3. **Notification Inbox** — role offer, cutoff, report ready, rank-up.
4. **Campaign Final Report** — финальная карта, timeline, Top-100 и эпилог.
5. **Settings & Accessibility** — звук, reduced motion, контраст, размер текста.

## 7. Общие системные состояния

Каждый основной экран обязан обработать:

- anonymous/no Reddit user;
- loading и повторную загрузку;
- offline/network error;
- Reddit rate limit;
- пустой список;
- недостаточные права/не та команда;
- действие уже выполнено;
- cutoff наступил во время заполнения;
- battle resolved между запросами;
- удалённый или ставший невалидным комментарий;
- campaign complete;
- mobile narrow viewport;
- keyboard focus, screen reader labels и reduced motion.

Все timestamps отображаются с явной зоной. Серверное время остаётся авторитетным.

## 8. Минимальные изменения модели и API

### 8.1. Order

```ts
type OrderRequest = {
  doctrineId: DoctrineId;
  sourceCommentId: string;
};

type DoctrineOrder = {
  battleId: string;
  army: ArmyColor;
  doctrineId: DoctrineId;
  sourceCommentId: string;
  sourceCommentPermalink?: string;
  submittedAt: string;
};
```

Сервер при submit повторно проверяет battle, автора, snapshot-команду, отсутствие
self-reference, время и существование комментария. Клиентская фильтрация не
является защитой.

### 8.2. Профиль

Публичная DTO должна собираться отдельным allowlist mapper. История участия должна
строиться из event participants и progression ledger, а не из текущего flair.

### 8.3. Daily leaderboard

Источник: participants + player + progression ledger + battle-local mission
outcome. Нужны server-side pagination и отдельная `currentUserEntry`.

### 8.4. Медали

Создать каталог с устойчивым `medalId`; хранить в профиле ID и award records.
Файлы `medal_001.webp`…`medal_114.webp` не должны сами определять смысл награды.

### 8.5. История боя

Capture record сейчас достаточен для истории владения, но не для полного replay.
Нужен `GET /api/battles/:battleId/public-result` или расширенная безопасная запись.

## 9. Пул растровой и пиксельной графики

### Обязательно для P0

- 7 doctrine icons/cards;
- 3 армейских identity набора: Green, Blue, AI;
- 30 territory thumbnails либо 6–10 переиспользуемых terrain families для теста;
- 1 command-center background;
- 1 strategic-map frame и owner markers;
- 3 battle-result banners;
- rank presentation для уже существующих 48 изображений;
- locked/earned medal frames;
- UI sprites: panel corners, buttons, tabs, dividers, cursors;
- battle FX mapping для существующих explosion/smoke/fire/impact sprites.

### Правила генерации

- сначала утвердить один visual target на ключевом Command Center;
- генерировать изображения под измеренные слоты, не растягивать случайные арты;
- сохранять единые palette, pixel scale, outline и lighting direction;
- декоративные изображения — raster; текст, формы, dropdown, таблицы — DOM;
- не генерировать fake UI с текстом внутри изображения;
- для каждого ассета вести manifest: purpose, dimensions, prompt, seed/variant,
  source file и место использования.

## 10. Порядок реализации

### Волна A — замкнуть механику Order

1. Eligible comments API и серверная валидация.
2. Comment Picker.
3. Doctrine Picker.
4. Review/Confirm.
5. Locked state и ошибки cutoff.

**Готово, когда:** игрок может вступить и отправить единственный валидный Order,
обязательно основанный на комментарии сокомандника.

### Волна B — сделать результат понятным

1. Расширенный Daily Report.
2. Progression ledger в API.
3. Daily leaderboard.
4. Territory details и battle replay summary.

**Готово, когда:** игрок понимает, почему победила сторона и что лично получил.

### Волна C — идентичность и возврат

1. Личный профиль.
2. Публичный профиль и share link.
3. Медали.
4. Архив битв и глобальный leaderboard.

**Готово, когда:** результат дня сохраняет долгосрочную ценность и им можно делиться.

### Волна D — контрразведка

1. Правило попытки и scoring.
2. Candidate comments API.
3. Выбор подозреваемого и подтверждение.
4. Результат в Daily Report без автоматической травли/деанонимизации.

### Волна E — визуальный production pass

1. Три концепта Command Center.
2. Выбор одного направления.
3. Генерация raster/pixel asset kit.
4. Применение к P0/P1.
5. Mobile, accessibility и performance QA.

## 11. Чек-лист готовности к тестам

### P0 функционально

- [ ] Новый игрок проходит цикл без ручного вмешательства администратора.
- [ ] Order всегда содержит валидный чужой командный комментарий.
- [ ] Повторный Order не изменяет зафиксированный выбор.
- [ ] Все семь доктрин объяснены в интерфейсе.
- [ ] Cutoff согласован с серверным временем.
- [ ] Resolver публикует один идемпотентный результат.
- [ ] Игрок видит личный XP breakdown и новые medals.
- [ ] Daily leaderboard содержит текущего игрока.
- [ ] Карта и история территории отражают resolve.
- [ ] Контрразведка ограничена и не превращается в публичное обвинение.

### P0 визуально

- [ ] Интерфейс читается на desktop и mobile Devvit webview.
- [ ] Основное поле боя не закрыто постоянными панелями.
- [ ] Green, Blue, AI и contested различаются не только цветом.
- [ ] Все изображения имеют корректные размеры и не размываются.
- [ ] Reward reveal поддерживает reduced motion.

### Наблюдаемость теста

- [ ] Логируются join, comment selection, order submit, spy suspicion и report open.
- [ ] Ошибки имеют battleId/user-safe correlation ID.
- [ ] Можно проверить участников, Orders, ledger и leaderboard без изменения данных.
- [ ] Есть demo battle с ускоренным cutoff и тестовыми комментариями обеих команд.

## 12. Решения и открытые вопросы

### Зафиксировано текущей реализацией

- Первый тест использует карту **30 территорий, 6×5**.
- Расширение до 150 территорий остаётся следующей фазой; UI не должен жёстко
  зависеть от 30 DOM-элементов.
- Order неизменяем после отправки.
- Публичный профиль не раскрывает активные скрытые игровые данные.

### Требует продуктового решения до соответствующей волны

1. Сортировка ежедневного leaderboard.
2. Число контрразведывательных попыток и формула результата.
3. Политика declassification шпионов.
4. Публичный slug: Reddit username или отдельный непрозрачный идентификатор.
5. Показывать ли точную историю Green/Blue службы в публичном профиле.
6. Полный mapping 114 medal assets на канонические награды.

## 13. Рекомендуемый следующий шаг

Начать с **волны A**. Она является главным функциональным разрывом между текущим
клиентом и каноническим игровым циклом. До её завершения генерация полного набора
экранов и ассетов создаст красивый интерфейс вокруг неполного Order-контракта.

## 14. Статус реализации на 2026-07-15

Основной тестовый контур закрыт: реализованы все P0-экраны, личный и публичный
профиль, Daily и Global leaderboard, публичный battle report, карта с историей,
контрразведка и Doctrine Codex. Существующие 30 растровых полей боя, 48 rank
insignia, две канонически подключённые medal images и пиксельная матрица доктрин
используются непосредственно интерфейсом.

Не являются блокерами первого полного теста и намеренно не имитируются
заглушками: P2 Role Mission Center (Captain/Deputy исключены из текущего
resolver), Notification Inbox (нет канонического delivery-контракта), полная
declassification шпионов и mapping оставшихся medal assets. Settings частично
покрываются системным `prefers-reduced-motion`; финальный campaign report уже
публикуется сервером и открывается из campaign state карты после завершения.

Проверено: targeted ESLint, `npm run test:core`, `npm run type-check`, production
build и мобильный Devvit playtest. Интерактивные join/order/suspicion действия в
живом дневном бою не отправлялись во время read-only QA, чтобы не менять
состояние тестового участника.
